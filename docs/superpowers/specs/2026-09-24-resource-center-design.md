# Web Studio 資源中心設計規格

日期：2026-09-24。狀態：設計規格 checkpoint；使用者決定回家再進 plan，尚未實作。

## 1. 目的與邊界

使用者從 source-only checkout 啟動本機 Web Studio 後，能在「資源中心」用點擊方式補齊車牌定位模型與訓練影像，清楚看到下載、校驗、授權及啟用狀態。下載與啟用是兩件事；下載完成不代表模型已接入 Reader、訓練集已被本次任務採用，或素材可公開發行。

首版只收錄三個固定資源：Morsetechlab YOLO11n ONNX 車牌定位模型、TLPD 3,032 張四角標註圖、EZCon 台灣車牌偵測訓練集。現有 EZCon OCR 辨識測試集保留為「評測資料」，不能與 EZCon 偵測訓練集混稱，也不得意外納入訓練。後續新增來源走受版本控制的來源定義與審查，不提供任意 URL 輸入框或自動抓取不明來源。

本規格不處理 SAM 3 自動標註、OCR 重訓、通用模型市集、公開帶權重 release 或多機部署。多版本訓練模型的登錄、比較、手動升版與回退，作為模型登錄契約保留；完整比較與發行流程另立規格。

## 2. 現況與選擇

- `web/index.html` 已有 TLPD 與 EZCon OCR 測試集的下載頁；`src/plateai_web/downloader.py` 及 `app.py` 有任務與 API。EZCon 偵測訓練集已有 `tools/fetch_ezcon_detection.py`，但尚未接上 Web 卡片。
- 既有 EZCon OCR Web 下載器會自行附加 `--acknowledge-unreviewed-license`。這使 CLI 的確認機制在 Web 路徑被跳過；資源中心落地時，舊入口也必須改走同一個明確確認檢查，不能留下繞道。
- `src/plateai_web/training_store.py` 已示範標準庫 SQLite 的短連線與 autocommit；資源狀態另設本機 SQLite，不混入訓練任務表。資料檔、權重與完整日誌留在被 Git 忽略的目錄，資料庫不保存影像或模型二進位。
- 現有 Reader 要求原生 pose 模型輸出四角；Morsetechlab 候選只有 bbox。它在本機 295 張偵測測試的 bbox recall 可用，但兩張機車照經現有 OCR 仍讀錯。因此「已下載」不能標成「已可辨識」。
- Studio 目前監聽 `0.0.0.0:1688`。新增及既有可到達的資源下載／切換寫入 API 預設只接受本機管理操作，並驗證請求來源；不能只靠前端警語或按鈕禁用。區網遠端管理若需要，另設身分驗證後再開放。

選用「版本控制的來源清單 + 本機 SQLite 狀態 + 既有背景任務」。不用純前端開關（重啟後不可信），也不用把遠端 URL 和授權文字完全交給可變資料庫（難以審查與重現）。

首版固定 TLPD revision `00f9ae2fa3d186bcf74e7f6ef4f48280181d6e85`、EZCon 偵測 revision `ab64ba1e86615c8371e1b5617792a130d45028e8`；現成模型以已在本機評測的 `license-plate-finetune-v1n.onnx` SHA-256 `693133a1db97a3ba1e90068986f80afb72c3fcddb681e57181a89a9a3dc351d6` 作預期內容，並固定可重取的上游版本。來源與目前權利記錄參見 [`docs/evaluation-sources.md`](../../evaluation-sources.md)、[TLPD 資料卡](https://huggingface.co/datasets/evan6007/TLPD)、[EZCon 偵測資料卡](https://huggingface.co/datasets/EZCon/taiwan-license-plate-detection)及[現成模型卡](https://huggingface.co/morsetechlab/yolov11-license-plate-detection)。若上游版本或檔案雜湊變更，須修改受控來源定義並重新審查，不自動接受最新檔案。

EZCon 確認須在按下下載時顯示來源、版本、限制，並由使用者明確確認；後端要求本次請求的確認欄位，並記錄確認的來源版本與時間。前端不能偷偷傳入預設 `true`。版本或警語文字變更後須重新確認。舊 Web 路徑不得無條件代傳 CLI 確認旗標。

每張卡顯示 `未下載／下載中／已驗證／驗證失敗`、來源版本、校驗與上次錯誤；可重試中斷下載。開關只改用途，不刪檔。TLPD 與 EZCon 可同時開啟，但未驗證資源不得啟用；任何訓練請求必須記錄當時的來源版本快照，不能因日後切換而改變既有 run 的來源。

## 4. 儲存與狀態契約

Git 追蹤的來源定義保存穩定 `resource_id`、類型、上游識別與固定 revision、下載器、預期內容及授權提示。下載入口只接受白名單 `resource_id`，不接受使用者提交的 URL、任意路徑或命令列。下載器沿用既有固定來源與雜湊校驗；寫入忽略目錄內的暫存位置，完成校驗後再發布，不覆蓋既有有效資源，也不自動刪除不明檔案。

本機 SQLite 記錄每個資源版本的任務 ID、目標相對路徑、狀態、校驗摘要與時間、錯誤、用途開關和 EZCon 確認紀錄。模型版本另記模型 ID、來源、檔案雜湊、輸出契約（`bbox` 或 `quad`）、驗收結果與是否為現役；多組可共存，但現役定位器最多一組。SQLite 是操作索引，不是檔案完整性的唯一證據：啟動、下載完成及啟用前都要核對路徑、完成標記與必要校驗。資料庫遺失可由受控檔案重新掃描；不得僅憑舊 `ready` 記錄宣稱可用。

任務狀態為 `pending → downloading → verifying → ready` 或 `failed`。重複點擊同一來源不啟動第二份下載，回傳既有任務或明確衝突。程序中斷後將未完成工作顯示為「待核對／可重試」，不得把殘留暫存檔當成功。下載權重只代表取得模型；切換前仍要通過格式、輸入輸出、bbox/quad 轉接、至少一張全圖的端到端 smoke test。切換失敗時保留原現役版本，沒有可用模型時回明確錯誤而非假結果。

## 5. Web 與下游介面

資源中心取代現有「下載驗證資料」的混合描述，三張主要卡片與現有 OCR 評測資料分區顯示。沿用既有背景任務進度／日誌 UI；頁面重載後從後端重建狀態，不信任瀏覽器本地儲存。

後端提供唯讀資源列表、按白名單 ID 啟動下載、設定訓練用途、列出本機模型及切換現役模型的受控操作。使用同一套校驗與警語規則處理舊路由；API 對未確認、未校驗、不相容模型、下載中及切換衝突回明確狀態碼與理由。不得因 UI 選中 bbox 模型就直接傳四個 bbox 角給 M3a 並宣稱透視校正成功；bbox 模型須經專用轉接／裁切驗收才開放啟用。

訓練入口只接受資源中心建立的已驗證來源快照，若選中的來源尚未由該訓練流程支援，應拒絕並顯示原因，不能靜默忽略開關。模型候選訓練完成後不自動覆蓋現役版本；公開 release 繼續 source-only，任何本機帶模型部署包都依所選模型的來源與權利狀態另作審核，不由資源開關自動授權。

## 6. 驗收

1. 全新 clone 在沒有資料與模型的狀態啟動，三卡顯示未下載；點選 TLPD 後取得並驗證 3,032 組圖片／標註，資料仍不進 Git。
2. EZCon 未確認時，直接呼叫新舊 Web 下載 API 都被拒絕；明確確認後才能下載，且確認只對當前來源版本有效。EZCon 預設不納入訓練。
3. 網路中斷、重複點擊、Web 重啟、校驗失敗或本機檔案被移動時，頁面不報假成功，能看出原因並安全重試；SQLite 與實體檔不一致時以校驗結果為準。
4. 可同時保留多組已訓模型；新版本不自動升版。現成 bbox 模型在轉接及端到端驗收前僅標示「已下載／尚不可啟用」；通過後切換失敗仍維持原現役版本。
5. 資源管理寫入 API 從非本機來源不可操作，舊路由沒有繞過警語的路徑；公開 source-only 打包不夾帶資料、ONNX 或本機 SQLite。
6. 以固定測試驗證 API、SQLite 重啟持久性、狀態重建、校驗及警語；瀏覽器手動驗收三卡、警語與開關。這些本機證據不得稱為真實車牌辨識率或 production 驗收。

## 7. 待後續獨立規格處理

- 多版本模型的固定測試集比較、人工升版門檻、回退及發行選擇。
- bbox 定位器的幾何細化與 OCR 品質提升；現有兩張機車照仍是辨識失敗案例。
- SAM 3 本機預標註、人工校正與自有資料來源擴充。
- 供兩個網站呼叫的真實獨立 Web API 與本機帶模型部署包；目前 1788 發行物仍是 source-only 雛形。
